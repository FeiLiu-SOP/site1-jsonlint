JSON Repair — Find and Fix Broken JSON

JSON repair means fixing syntax so JSON.parse succeeds: remove trailing commas, fix quotes, close brackets, and strip invalid comments. Many teams search json repair or jsonlint repair after copying API responses, LLM output, or legacy config files.

Common fixes before you validate

  • Trailing commas — delete the comma after the last property in { } or [ ].
  • Single quotes — JSON requires double quotes around strings and keys.
  • Unclosed braces — match every { with } and [ with ].
  • Comments — standard JSON does not allow // or /* */; remove or move to docs.
  • Truncated streams — paste only complete objects; split NDJSON line-by-line if needed.

Repair workflow (validate + format)

  1. Paste broken JSON into the tool.
  2. Click Validate — read the error line/message.
  3. Apply a small fix and validate again.
  4. Click Format when parsing succeeds.

Our validator runs entirely in your browser — suitable for tokens and private payloads while you repair and re-check syntax.

JSON repair vs dedicated auto-fix tools

Some sites auto-fix LLM markdown fences and smart quotes. This tool focuses on clear validation errors + pretty-print so you control each edit — a simple alternative when you want a lightweight jsonlint-style checker without uploading data.
